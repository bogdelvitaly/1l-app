# 1L — учёт мастерской

PWA-приложение для учёта продаж, доходов, расходов, квартальных отчётов и подарочных сертификатов.

## Стек

Next.js 16 (App Router) · Prisma · SQLite (dev) / PostgreSQL (prod) · Auth.js (Credentials) · ExcelJS · pdf-lib

## Запуск локально

```bash
npm install
npm run db:push     # создаёт локальную SQLite-базу prisma/dev.db по схеме
npm run db:seed     # создаёт первого пользователя (admin / admin1234) и 7 типов товара
npm run dev
```

Открыть http://localhost:3000, войти как `admin` / `admin1234`, сменить пароль в /settings.

## Импорт старого Excel-файла

Можно либо через интерфейс (**Настройки → Импорт / экспорт Excel**, файл или ссылка), либо разово из консоли:

```bash
npm run import:legacy -- "C:\путь\к\Бухгалтерия.xlsx" admin
```

Ожидает вкладки с именами `Расходы {год}` и `Доходы {год}` в том же формате, что и исходный файл (см. `src/lib/legacyImport.ts` — там же комментарии с точным номером колонок). Импорт можно запускать повторно на обновлённом файле — новые строки просто добавятся, дубли не проверяются (при повторной загрузке того же файла записи задвоятся).

## Себестоимость по типам товара

Каждый тип товара (В-К, В-В, М-30 и т.д. — сами по себе редактируемые в /settings) состоит из компонентов (название + цена). Себестоимость типа = сумма цен компонентов. Изначально у каждого типа один компонент-заглушка «Стоимость себестоимости типа» с ценой 0 — удалите его и добавьте реальные компоненты (материалы, работу и т.п.).

## Переход на боевую БД (PostgreSQL / Neon)

Локально используется SQLite (`prisma/dev.db`, в .gitignore, не коммитится). Для продакшена:

1. Создать Postgres-базу (например, [Neon](https://neon.tech) — есть бесплатный тариф, легко подключается к Vercel).
2. В `prisma/schema.prisma` поменять `provider = "sqlite"` на `provider = "postgresql"`.
3. Задать `DATABASE_URL` в переменных окружения Vercel на connection string от Neon.
4. `npx prisma db push` (или `migrate deploy`) на боевой базе.
5. Задать `AUTH_SECRET` (см. `.env.example` — команда для генерации).

Никаких других изменений в схеме не требуется — enum'ы нигде не используются (везде строки + валидация в коде), поэтому схема одинаково работает и на SQLite, и на Postgres.

## Что не реализовано (сознательно, за рамками MVP)

- Автовыгрузка на Google Диск раз в месяц — отложена по просьбе пользователя, добавить позже через Google Drive API + Vercel Cron поверх уже готового `/api/export`.
- Офлайн-режим — приложение всегда требует интернет (так и задумано), PWA только для установки на экран.

## Структура

- `src/app/(app)/*` — основные разделы (Доходы, Расходы, Отчёты, Сертификаты, История, Настройки), защищены через layout-проверку сессии.
- `src/lib/reports.ts` — вся логика квартального отчёта (налог, себестоимость, остаток).
- `src/lib/formulas.ts` — налоговая формула и границы кварталов/месяцев.
- `src/lib/legacyImport.ts` — парсер легаси-Excel, используется и CLI-скриптом, и загрузкой из /settings.
- `src/app/api/export/route.ts` — экспорт текущих данных в .xlsx по годам.
- `src/app/api/certificates/[id]/pdf/route.ts` — генерация PDF сертификата (шрифт PT Sans в `src/assets/fonts`, т.к. стандартные PDF-шрифты не поддерживают кириллицу).
